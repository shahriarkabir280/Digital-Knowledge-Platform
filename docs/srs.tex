\chapter{Problem Definition}

\section{Problem Statement}

\subsection{What problem are we solving?}

Academic institutions face significant challenges in managing and providing access to their digital knowledge resources. Current systems are fragmented, with separate platforms for library management, research repositories, digital archives, and student project showcases. This fragmentation leads to:

\begin{itemize}
    \item Difficulty in discovering relevant academic resources
    \item Lack of proper research output visibility and impact tracking
    \item Inefficient library operations and poor user experience
    \item Limited support for Bangla language content and bilingual research
    \item No collaborative tools for knowledge sharing and annotation
    \item Poor preservation of institutional knowledge and historical documents
    \item Absence of advanced analytics on research trends and usage patterns
    \item Limited academic integrity checking mechanisms
\end{itemize}

\subsection{Why does it matter?}

A unified Digital Knowledge Platform is essential for:
\begin{itemize}
    \item Enhancing research productivity and collaboration
    \item Improving accessibility of knowledge resources for students and faculty
    \item Preserving institutional heritage and research outputs
    \item Supporting bilingual (Bangla-English) academic work
    \item Providing data-driven insights for academic planning
    \item Streamlining library operations and reducing administrative overhead
    \item Fostering academic integrity and quality research outputs
\end{itemize}

\section{Goals and Non-Goals}

\subsection{Goals}
\begin{itemize}
    \item Create a unified platform integrating digital archive, research repository, library catalog, and project showcase
    \item Support multi-format media (PDF, DOCX, audio, video, images) with rich metadata
    \item Implement bilingual (Bangla-English) support with advanced NLP features
    \item Provide AI-powered research assistance and smart recommendations
    \item Enable collaborative annotation and knowledge sharing
    \item Offer comprehensive library management with lending/return workflow
    \item Implement tiered access control (public/member/staff/restricted)
    \item Provide analytics dashboard for research trends and usage patterns
    \item Ensure academic integrity through plagiarism detection and citation checking
    \item Support digital preservation with format health monitoring
    \item Create virtual reading rooms for collaborative study
    \item Implement smart citation management with multiple format support
\end{itemize}

\subsection{Non-goals}
\begin{itemize}
    \item Course management or LMS features (covered by existing systems)
    \item Financial transactions or e-commerce (except fine management)
    \item Video conferencing infrastructure (integrate with existing tools)
    \item Email server or communication platform
    \item Mobile app development (initial version is web-based with responsive design)
    \item Content creation tools (editors, graphic design software)
\end{itemize}

\section{Assumptions and Constraints}

\subsection{Technical Constraints}
\begin{itemize}
    \item Web-based responsive application (desktop and mobile browsers)
    \item Must support modern browsers (Chrome, Firefox, Safari, Edge - last 2 versions)
    \item Maximum file upload size: 500MB per file
    \item Server infrastructure availability (provided by institution)
    \item MVP core features shall function without external cloud API dependencies
    \item Optional cloud service integrations (Phase 2) require institutional Memoranda of Understanding (MoU) and network access policies
    \item If cloud APIs are used, implement graceful fallback to self-hosted alternatives
\end{itemize}

\subsection{Organizational Constraints}
\begin{itemize}
    \item Access to institutional data for migration
    \item Availability of existing library database
    \item User training resources for librarians and staff
    \item Institutional policies on data privacy and access control
\end{itemize}

\subsection{Timeline Constraints}
\begin{itemize}
    \item SRS completion: Lab 2
    \item Peer review: Lab 3
    \item Implementation of Sprint 1,2: Lab 4,5
    \item Peer UI critique: Lab 6
    \item Testing baseline: Lab 7
    \item Peer QA: Lab 8
    \item Hardening and Deployment Readiness: Lab 9
    \item Testing and deployment by semester end
\end{itemize}

\subsection{Assumptions}
\begin{itemize}
    \item Users have basic computer literacy
    \item Internet connectivity available
    \item Institution provides server resources and backup systems
    \item Existing library data can be exported in standard formats (CSV, MARC)
    \item Copyright clearance obtained for uploaded content
    \item Users have valid institutional email addresses
\end{itemize}

\section{Deployment Objective}
\textbf{MVP (Phase 1):} The MVP shall be deployable in university-managed, on-premises infrastructure using self-hosted or locally-available services. Advanced AI features (summarization, plagiarism detection, OCR) shall have self-hosted reference implementations (Hugging Face models, Tesseract, local plagiarism baseline).

\textbf{Phase 2 (Optional):} Cloud API integrations (OpenAI, Google Cloud, Turnitin) may be added as optional enhancements if institutional Memoranda of Understanding (MoU) and network policies permit. No Phase 1 core feature shall require cloud APIs to function.

\section{On-Premises Reference Architecture (MVP)}

\textbf{Minimum Runtime Components:}
\begin{itemize}
    \item Reverse proxy and TLS termination (Nginx or equivalent)
    \item Frontend web service
    \item Backend API service(s)
    \item Background worker service for async jobs (OCR, summarization, plagiarism)
    \item PostgreSQL database
    \item Redis cache and queue broker
    \item Elasticsearch for search
    \item Object/file storage for documents and backups
\end{itemize}

\textbf{Network Segmentation:}
\begin{itemize}
    \item DMZ/public zone: reverse proxy only
    \item Application zone: frontend, API, workers
    \item Data zone: database, search, cache, storage
    \item Management zone: monitoring, logging, backup/restore tooling
\end{itemize}

\section{Glossary}

\begin{description}
    \item[Access Tier] Permission level (public, member, staff, restricted) determining who can view content
    \item[Annotation] User-created note or highlight on a document
    \item[Bangla NLP] Natural Language Processing for Bangla language (stemming, synonyms)
    \item[Citation Network] Graph showing relationships between papers through citations
    \item[Digital Preservation] Long-term storage and accessibility of digital content
    \item[DOI] Digital Object Identifier - unique persistent identifier for documents
    \item[Lifecycle State] Status of document (draft, review, published, archived)
    \item[MARC] Machine-Readable Cataloging - library metadata standard
    \item[OCR] Optical Character Recognition - extracting text from images
    \item[Repository] Organized collection of documents and research outputs
\end{description}
